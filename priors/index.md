# priors/ — the repo prior library (teacher read-set; the student never sees it)

Architecture decision maps of the published kernels under `kernels/`: per kernel, the
decisions that define its machine (persistent scheduling, warp roles, pipeline depth, data
residency, epilogue path, shape domain) in prose — **decisions and values, never an
implementation body**. A distilling teacher reads the top-k entries matching the task's
operator family before authoring M0, the way a human would review reference designs; every
idea a prior plants still goes through this run's own measurement (ARCH_PROBE / SWEEP /
probe) before it influences anything.

Skeletons for the remaining kernels are generated by `scripts/build_priors.py --write`
(metadata + empty sections); the filled files are the quality bar. A file whose
`Status: filled` line is present is never overwritten by the script.

## Find by operator family

- **GEMM dense/FP8** — `gemm/fp8_gemm_h100.md`: persistent cluster-tile loop, 3-stage TMA
  ring, A-multicast, STSM+single-shot TMA-store epilogue.
- **Attention (dense, causal, GQA)** — `attention/attn_fwd_gqa16_h100_gen2.md`: persistent
  zigzag schedule, producer warp + consumer ping-pong, Q double-slot prefetch, resident
  fp32 row state.
- **Conv (im2col supply spine)** — `conv/conv3d_fwd_h100.md`: im2col-mode TMA activation
  gather, transposed-view weight TMA, merged expect_tx stage barrier, register-resident
  accumulators.
- Everything else — `python3 scripts/build_priors.py` lists the skeleton to fill
  (sparse attention, paged decode/prefill, linear attention, grouped GEMM, conv
  gradients, the CUDA post-paper kernel).

## Find by feature (what you are trying to decide)

- *Persistent vs data-parallel grid, tail absorption* → all three filled maps
  (persistent loop, zigzag schedule, wave-count arithmetic).
- *Producer/consumer warp specialization and the register split* → fp8_gemm (40/232),
  conv3d (40/232 + min-blocks pin), attention fwd (named-barrier ping-pong).
- *Ring depth and rendezvous budget* → fp8_gemm (3 stages, 3 blocking waits per k-block),
  conv3d (merged expect_tx), attention fwd (2-stage ring + Q shadow round).
- *Cluster multicast / DSMEM-style sharing* → fp8_gemm (A + scale multicast across the
  cluster pair).
- *Epilogue without atomics or a second kernel* → all three (STSM single-shot store,
  per-WG smem slab, ping-pong TMA store).
- *Hardware doing the data movement the software used to do* → conv3d (im2col TMA,
  transposed-view descriptor).

## Adding a map

Run `scripts/build_priors.py --write`, fill the six sections from the kernel's decision
comments and your own probes, flip the status line to `Status: filled`, add the family row
above. Red lines: decisions in your own words, no code bodies, no experiment narrative
(dates, job ids) — this is a library, not a lab notebook.
