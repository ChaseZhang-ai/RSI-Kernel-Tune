## Device changes and instruction counts

The short path uses four disjoint output stripes per row through B=40 and two through B=64. Rows through B=24 group four stripe CTAs along the stripe grid axis to share L2 reads. At higher short-batch occupancy, cluster size one lets CUDA balance placement across CTAs. Each CTA reduces the full row with the archived FP32 math and writes only its own BF16 output stripe. It uses one documented CUDA driver launch on the current stream. The unaligned route uses padded Triton. [CUDA launch API](https://docs.nvidia.com/cuda/cuda-driver-api/group__CUDA__EXEC.html)

NVRTC 13.0 SM 10.3 disassembly showed five 256-bit global loads, one 256-bit global store and eight paired FP32-to-BF16 conversions in the archived seven-stripe kernel. The 448-thread four-stripe kernel has three, one and eight respectively. The whole-row kernel stayed at six loads, two stores and sixteen paired conversions. These are static counts per kernel instruction stream, including predicated instructions. In the matched 224-thread seven-stripe experiment, mixed BF16/FP32 adds cut the non-padding instruction count from 212 to 196 while keeping memory and BF16 output conversion counts fixed. It did not consistently lower timing. The isolated scheduling result justified reusing the archived arithmetic. The Triton comparator passed numerical checks and timed more slowly.
