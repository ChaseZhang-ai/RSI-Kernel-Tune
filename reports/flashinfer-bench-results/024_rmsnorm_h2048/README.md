### Reproduce the DPS bundle

From the repository root with PyArrow and the SOL-ExecBench environment available, run the following after acquiring the shared GPU lock, confirming idleness and locking the clocks. Set `GPU_UUID` to the selected physical GPU's UUID.

```bash
op=024_rmsnorm_h2048
stage=.artifacts/rmsnorm024/repro
python "reports/flashinfer-bench-results/$op/make_bundle.py" \
  .artifacts/sol-data/FlashInfer-Bench.parquet \
  "flashinfer-bench/$op/submission.py" "$stage"
CUDA_VISIBLE_DEVICES="$GPU_UUID" sol-execbench "$stage/$op" \
  --solution "$stage/solution.json" --output "$stage/results.jsonl"
```

## Packed CUDA screen · 2026-11-26 18:45 UTC

All 119 workload/configuration trials passed correctness and timing. This screen used the same physical GB300 GPU 1, locks, clocks and evaluator method as the Triton screen. The first packed CUDA launch, including NVRTC compilation of the tuning variants for queried capability 10.3, took 0.366 s.

The 256-thread cooperative reduction with one L2 prefetch CTA and two compute CTAs per row won all five small workloads at 2.608–2.816 µs. It used 24 registers per thread, 32 bytes of shared memory and zero local memory. The 128-thread counterpart used 38 registers and 16 bytes of shared memory. The stat calculation uses packed FP32 math, two FP32 multiplies per output and a final BF16 conversion.

At batch 12,383, two rows sharing the cached weight vector reached 18.992 µs with 55 registers per thread. At batch 16,254, two parallel row groups with an L2 prefetch for an upcoming tile reached 23.296 µs with 33 registers per thread. These medians correspond to 5.34 and 5.72 TB/s of input-plus-output payload, respectively. The largest workload moves about 127 MiB of activation and output per call.
